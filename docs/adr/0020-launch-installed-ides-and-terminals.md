# Launch installed IDEs and terminals from the project directory

Opening a Project in an IDE or terminal uses detected, installed tools rather than hardcoded PATH short names. RepoAtlas resolves the canonical project directory first, then launches that directory with the selected tool. Windows GUI apps are started as GUI processes; consoles request a new console window. Discovery covers common Windows and macOS install locations, including Windows Terminal, PowerShell, Command Prompt, Git Bash, Cursor, VS Code, JetBrains Toolbox scripts, and macOS app bundles. Missing tools fail visibly instead of silently opening Explorer.

Opening a Project with an AI coding agent follows the same boundary. The project header exposes an Agent launcher ahead of the terminal and IDE launchers. Discovery covers desktop agent apps (Cursor, ZCode, OpenCode, Kimi, Antigravity, WorkBuddy, Grok, Qoder, Trae, Windsurf) and CLI agents (Claude Code, Codex, Kimi Code, OpenCode CLI, Gemini CLI, Qwen Code, Lingma). Desktop agents reuse the IDE launch path; CLI agents open a real terminal inside the project directory and start the detected binary there (Windows Terminal, PowerShell, or Command Prompt on Windows, Terminal.app via osascript on macOS). Listing stays read-only discovery of installed binaries: RepoAtlas never installs, updates, or rewrites other tools' configuration, and CLI agents receive only the canonical project directory.
