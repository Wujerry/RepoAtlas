# Run structured tasks in a PTY

An explicitly stopped Task Run is presented as “Stopped” (已停止), for all task kinds including long-running development services. Existing `cancelled` Task Run storage/protocol values and aggregate fields retain compatibility and mean a user-stopped process; they are not failures or successful builds. Cancellation wording remains available for operations withdrawn before execution and for canceled scans/refreshes.

RepoAtlas keeps the Command Broker's structured executable-plus-argv boundary, but live Task Runs now spawn through a portable PTY so commands can detect a terminal, emit ANSI color, and update progress in place. The desktop workbench owns xterm rendering, resize, and input focus; MCP still cannot start, write, resize, or stop a live process without desktop approval. Shell evaluation remains an explicit higher-risk exception, logs stay capped, and Windows Job Objects plus Unix process-group cleanup remain the stop guarantee.

Task completion follows the child process exit code, never output text or terminal EOF. An independent observer checks the process while the output reader drains concurrently. After exit, terminal handles close outside the Broker mutex (ConPTY closure can wait for output consumption), and the completion callback waits at most two seconds for remaining output. Explicit stop continues to reap the process and preserve the persisted cancellation status. The desktop publishes terminal status immediately on the exit event, independently of final log hydration, and ignores stale running responses for retained completed runs.
