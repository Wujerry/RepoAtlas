# Cache and bound Footprints history

Footprints is a desktop, local-history view. Its list, calendar summary and detail queries read only SQLite through the shared Core. Queries never trigger scanning or Git. The Tauri boundary uses explicit UTC second ranges computed from local calendar dates, including daylight-saving transitions, while events retain their original timestamp strings for display. List cursors bind the range, filters and stable time/ID position. Git IDs include the Project ID because Repository Lineage does not merge checkouts.

Each source is filtered, sorted and limited in SQL before a bounded union. Search applies before pagination, using bound parameters and a maximum 32-day query range. Lists omit bodies; detail queries use source primary keys. Expression indexes match numeric time predicates. Migration 21 aligns the secondary sort key with the complete stable activity ID, including its source prefix. Schema migrations 18–20 build derived hourly, six-hour and daily counts and maintain them through insert/update/delete triggers, including writes from another MCP connection. The calendar decomposes each local day into the largest aligned buckets and uses bounded source queries only for partial-hour timezone edges. Range queries force the matching time/project index rather than allowing a full-history group scan. Invalid historical timestamps are retained in storage but excluded from dated queries.

Git collection is a separate shared-Core scheduler. Preparing targets and persisting batches take short database locks; cancellable, 15-second-timeout local Git processes execute outside the lock, at concurrency two. Default scope is the current HEAD's reachable commits in the most recent 90 local days, without fetch. Explicit historical requests select a Project and a range no longer than 366 days. A pinned HEAD and 500-record batches prevent moving-HEAD pagination errors. Cache coverage records include successful empty repositories, HEAD, range and check/error status. A completed range is fresh for five minutes; failed requests back off for the same interval, with explicit retries allowed. Changed Project locations or removed records reject late persistence. Cancellation preserves completed batches without claiming complete coverage.

The frontend polls only active refresh jobs while visible, cancels automatic work on closure, and does not silently reorder a visible list when collection finishes. It keeps at most eight query caches with ten pages each; continuing beyond that window discards older in-memory pages. All existing synchronous history side effects in project registration, scanning and Git write completion are removed. No history execution tool is added to MCP; desktop and MCP retain the existing external execution boundary.

History cache tables are application data only. Upgrades never inspect or write managed directories. The first count migration necessarily visits existing cached records once; subsequent startup does not rebuild counts. SQLite connections use a bounded 64 MiB page-cache budget. List branches pin the matching time or Project/time index and use a source-first cross join before their local limit, avoiding planner regressions that multiply work by the Project count on large disk databases.
